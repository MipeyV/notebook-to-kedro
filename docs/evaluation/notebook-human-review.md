## Request and declared decision

Start from a saved [pipeline reference artifact](notebook-pipeline-artifacts.md), loaded against
its explicit source binding and capture. The reference must be complete, match its expectations,
observe **every planned task output**, and have known, stable original before/after runtime controls.
A successful final metric or partial observation inventory is insufficient. This is reference
readiness, not independent validation that the expectations themselves are correct.

`prepare_notebook_human_review` binds a request to the exact reference-artifact, source-binding and
expectation hashes. Fixture author identities are supplied explicitly, not inferred from a model
answer. The original provenance/exposure metadata remains in the reference binding. The request
starts with decision `pending`, no reviewer/date/revision/proof, independence false and four
unchecked sections. It never fills them from green tests or model agreement:

| Section ID | Review scope |
| --- | --- |
| `source_catalog` | Source cells, loaders, simulation, catalog and parameters. |
| `hand_expectations` | Independently checked rows, schemas, values, indices and comparison policies. |
| `structure_learning` | Task/wiring coverage, assertions, feature order, split alignment and leakage. |
| `oracle_sensitivity_execution` | Notebook/baseline reproduction, negative controls, runtime and limits. |

Use the [pilot worksheet](synthetic-pilot-review.md) for the detailed checks within each section.
Mark a section complete only after checking every applicable item, with non-empty reviewer notes.
Unsupported or failed checks require a new/corrected reference rather than silently checking the box.

`record_notebook_human_review` accepts caller-supplied decision fields and snapshots a non-empty,
project-local proof file. It preserves the request's author/reference identities and computes a new
record hash. The proof should contain the real reviewer, review date, actual full reviewed commit,
commands/results, corrections/rationale and evidence reference; original notebook/CSV/contract/
catalog bytes and all typed expectations are already bound through the reference artifact.
Dates use `YYYY-MM-DD`, revisions use full lowercase Git SHA1, and completed checks require notes.
The proof file is hashed, not semantically interpreted; records can be inspected even when incomplete,
rejected or model-declared. A non-pending decision cannot be amended through this API.

```python
from notebook_to_kedro.evaluation import (
    load_notebook_human_review,
    prepare_notebook_human_review,
    record_notebook_human_review,
    write_notebook_human_review,
)

# baseline was loaded from the exact saved reference, not an arbitrary notebook/model score.
request = prepare_notebook_human_review(baseline, fixture_author_ids=actual_author_ids)
write_notebook_human_review("generated/review-request.json", request)

# human_decision is supplied by the actual reviewer, never generated by a model or test result.
record = record_notebook_human_review(request, human_decision, project_root=".")
write_notebook_human_review("generated/human-decision.json", record)
inspected = load_notebook_human_review("generated/human-decision.json", project_root=".")
```

The decision mapping requires exactly `reviewer_id`, `reviewer_kind`,
`independent_human_review`, `review_date`, `reviewed_revision`, `decision`, `checks`, `corrections`,
`evidence_reference` and `evidence_path`. Checks are ordered `{section, completed, notes}` objects.
The proof path is relative to the project root; root escapes and changed/missing proof bytes fail.
Nullable fields and unchecked sections remain inspectable but cannot be promoted.

## Explicit operator acceptance

`promote_notebook_pipeline_artifact` requires `accept_human_review_evidence=True` **before I/O**
and a non-empty operator identity. The caller must have externally verified that the declaration
really came from the named independent human and covers the exact reviewed inputs. The library
rechecks current source/capture/reference evidence and proof bytes, then requires:

- exact reference/source/expectation identities;
- decision `approved`, reviewer kind `human` and independence literally true;
- complete reviewer identity/date/revision/corrections/reference and a bound non-empty proof file;
- all four sections complete with notes;
- reviewer identity distinct from every declared author after whitespace/case normalization.

Missing/rejected/model/author/incomplete evidence does not pass. Changed expectations, adapters,
capture, budgets or runtime evidence produce a different reference hash and require a new request.
Corrections are recorded text, not automatically applied to source or expectations.

The result is a separate `reviewed-notebook-contract-1` wrapper with the typed frozen reference,
human declaration, operator identity and its own hash. Exclusive publication preserves the original
draft contract, capture, artifact and pending metadata unchanged. The wrapper is not an approved
legacy `BehavioralCase`, live campaign manifest or retroactive model-accuracy result.

```python
from notebook_to_kedro.evaluation import (
    load_reviewed_notebook_contract,
    promote_notebook_pipeline_artifact,
    write_reviewed_notebook_contract,
)

contract = promote_notebook_pipeline_artifact(
    "generated/reference.json",
    binding,
    capture_directory,
    "generated/human-decision.json",
    project_root=".",
    operator_id=actual_operator_id,
    accept_human_review_evidence=True,
)
write_reviewed_notebook_contract("generated/reviewed-contract.json", contract)
verified = load_reviewed_notebook_contract(
    "generated/reviewed-contract.json",
    "generated/reference.json",
    binding,
    capture_directory,
    project_root=".",
)
```

Loading rechecks the stored wrapper, reference and local proof without executing code or making a
new human decision. Reference inspection does not require the reader's runtime to equal the original
runtime. Future execution still needs separate runtime compatibility and code-execution consent.
JSON/proof reads and review/wrapper publication default to 16 MiB per file, with strict duplicate-key/
non-finite JSON rejection and exclusive bounded writes. Existing reference-artifact bounds remain
separate; limits are not an OS security sandbox or total memory budget.

## Trust boundary and current result

**This is structural verification of externally supplied declarations, not identity authentication.**
A person, model or attacker can falsely label a record `human`, omit author aliases, invent notes,
give a fictitious commit or rewrite all files/hashes. Commit existence/content, human identity,
independence, reference links and proof prose are not authenticated by this library. Operator
acceptance is an explicit trust decision, not cryptographic signing or an access-control system.
Before a hosted/live workflow, organizations must supply authenticated reviewer/operator provenance,
appropriate access controls, storage/privacy policy and isolation. Never set the flag on behalf of
a model-generated assessment. File rechecks are point-in-time, not locks against concurrent edits.

Positive unit tests use explicitly synthetic reviewer/operator identities and fabricated transport
in temporary roots only; they test schema/gate mechanics and do **not** approve any real fixture.
The actual nine-node pilot prepares only a pending request and verifies promotion is refused,
despite seventeen matched observations. Its committed review remains pending, with no real proof
record or reviewed wrapper published and no whole-notebook LLM call.
